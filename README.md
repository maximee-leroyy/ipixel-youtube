# ipixel-youtube

Live YouTube subscriber counter for an **iPixel Color 32×32** LED matrix.

The script gets the subscriber count of a YouTube channel, pixelates the logo (SVG) with [pyxelate](https://github.com/sedthh/pyxelate), builds the 32×32 image, and sends it to the panel over Bluetooth with [pypixelcolor](https://lucagoc.fr/pypixelcolor/main/).

## Architecture

```text
assets/                  # local output, gitignored
  preview/               # generated by --preview
  personal/              # local --image drawings
src/ipixel/
  cli.py                 # Click + live loop
  log.py                 # single log format (Python + entrypoint)
  assets/youtube.svg     # official Simple Icons logo (only source of the logo)
  youtube/               # cookies, Studio, public APIs
  display/               # bitmap fonts, pyxelate logo, GIF, BLE (device.py)
container/entrypoint.sh  # host or local BlueZ, then python -m ipixel
tests/
```

## Requirements

- Python 3.13.7
- An iPixel Color panel (tested with 32×32)
- Bluetooth on, panel powered on

```bash
nerdctl compose run --rm ipixel scan

nerdctl compose up -d
```

Without Compose:

```bash
nerdctl run --rm --network host --privileged \
  -v /run/dbus/system_bus_socket:/host/dbus/system_bus_socket \
  -v ./cookies.txt:/app/cookies.txt \
  -e IPIXEL_ADDRESS=AA:BB:CC:DD:EE:FF \
  ghcr.io/maximee-leroyy/ipixel-youtube:latest
```

`--print-count` / `--preview` / `--source live`: `nerdctl compose run --rm ipixel --print-count`. Drawing: `-v ./my.gif:/app/drawing.gif:ro` then `--image /app/drawing.gif`.

Scan and BLE panel: **Linux** (Pi 5), with the host BlueZ running (`sudo systemctl enable --now bluetooth`). On Mac, nerdctl runs in a VM with no HCI: `--print-count` only.

Local build: `nerdctl compose build`. The image is published to GHCR on every push to `main` (Actions → Container image). The GHCR package is private after the first push: Package settings → Change visibility → Public.

Update a running container: `nerdctl compose up -d` does not recreate a container that is already running, even if the image changed. You need:

```bash
nerdctl compose pull ipixel
nerdctl compose up -d --force-recreate ipixel
```

## Several panels

One compose service per panel, each with its own `IPIXEL_ADDRESS` and `YOUTUBE_CHANNEL`, all with `network_mode: host`:

```yaml
services:
  ipixel-a:
    image: ghcr.io/maximee-leroyy/ipixel-youtube:latest
    container_name: ipixel-a
    restart: unless-stopped
    network_mode: host
    privileged: true
    volumes:
      - /run/dbus/system_bus_socket:/host/dbus/system_bus_socket
    environment:
      IPIXEL_ADDRESS: AA:BB:CC:DD:EE:01
      YOUTUBE_CHANNEL: "@channelA"
      YOUTUBE_SOURCE: live
      TZ: Europe/Paris
  ipixel-b:
    # same, with the IPIXEL_ADDRESS / YOUTUBE_CHANNEL of the 2nd panel
```

What the code does to make this work (`src/ipixel/display/device.py`):

1. **Old connection closed.** A killed container (SIGKILL) leaves the panel "connected" in the host BlueZ. A connected panel stops advertising, so the scan does not find it (`BleakDeviceNotFoundError`). Before each connection: `bluetoothctl disconnect <address>`.
2. **One scan+connect at a time.** The containers share the same Bluetooth chip, and BlueZ fails LE connections started at the same time. A lock (abstract UNIX socket `ipixel-ble-connect`) makes them go one after the other. It is shared because abstract names belong to the network namespace ([network_namespaces(7)](https://man7.org/linux/man-pages/man7/network_namespaces.7.html)): this is why `network_mode: host` is required. The kernel releases it if the process dies.
3. **Retries.** In live mode, the connection is retried forever: 3 s, 6 s, 12 s… capped at 60 s (+0 to 2 s at random to spread the containers apart). With `--once` or `--image`: 3 tries, then exit code 1.
4. **Clean stop.** `docker stop` / `nerdctl stop` sends SIGTERM ([Docker docs](https://docs.docker.com/reference/cli/docker/container/stop/)). The CLI turns it into a normal exit, which closes the BLE link. After a SIGKILL, step 1 cleans up on the next start.

Steps 1 and 2 only apply to Linux (BlueZ). On macOS, CoreBluetooth handles it by itself.

Cookies: with `--source studio`, the script rewrites `cookies.txt` when Google sends new cookies. Two containers must **not** share the same file in studio mode: give each channel its own file (`YOUTUBE_COOKIES`). With `--source live` the file is not read.

## Logs

A single definition: `src/ipixel/log.py`. The CLI, pypixelcolor, bleak and the container entrypoint (`python -m ipixel.log LEVEL message`) all write to stderr in this format:

```text
2026-11-11T20:04:30.488+01:00 INFO    [@myChannel] Connected to panel AA:BB:CC:DD:EE:FF (32x32)
```

- **Date**: ISO-8601, milliseconds, UTC offset. Time zone = `TZ` variable (e.g. `Europe/Paris`), UTC if empty.
- **Level**: `DEBUG`, `INFO`, `WARNING`, `ERROR`.
- **Tag**: the channel (`--channel`), otherwise the BLE address. Used to tell panels apart in `nerdctl compose logs`.
- Multi-line messages (tracebacks, help) are indented under their dated line.
- Without `--debug`, pypixelcolor and bleak only show warnings (pypixelcolor logs every BLE command).
- Only exception: the `--print-count` result goes to stdout, as plain text, so a script can read it.

## Find the panel

```bash
nerdctl compose run --rm ipixel scan
```

Write down the Linux address (MAC `AA:BB:CC:…`), not a macOS UUID:

```text
LED_BLE_XXXXXXXX (AA:BB:CC:DD:EE:FF)
```

## Run

The **exact** count (the one in YouTube Studio → *Current subscribers*, e.g. 1,093) is not public. You need the owner's session.

1. Sign in to [YouTube Studio](https://studio.youtube.com) with the channel's account
2. Export the cookies (Chrome extension **Get cookies.txt LOCALLY**)
3. Save the `cookies.txt` file at the root of the project (already in `.gitignore`)

```bash
ipixel-youtube
# same as:
python -m ipixel
```

Check the count without Bluetooth:

```bash
ipixel-youtube --print-count
```

The panel shows the name, the subscriber count in cyan, and a looping **shine** (short GIF, not stored in ROM). Ctrl+C stops the live mode. `--static` sends a still PNG. `--save-slot` requires `--static` (refused otherwise: a GIF in ROM can brick the panel); only use it after the display looks right.

If a request fails, the panel keeps the image it already has and the error is logged once. If the channel name cannot be found, the CLI stops (code 1): pass `--name`.

## Show a drawing (without the YouTube HUD)

Instead of the YouTube icon + counter + channel name, you can send any PNG, JPEG or GIF. The image is cropped/resized to **32×32** (nearest-neighbor, centered on a black background — ideal for pixel art).

Make a 32×32 PNG (Aseprite, Piskel, Photoshop…) then:

```bash
# LED simulation without Bluetooth
ipixel-youtube --image drawing.png --preview

# Send to the panel
ipixel-youtube --image drawing.png --address AA:BB:CC:DD:EE:FF
```

An animated GIF is sent as is (looping). `--static` sends only the first frame as a PNG (required with `--save-slot`).

Generates `./assets/preview/preview.gif` (relative to the current folder) as a large LED simulation (the raw 32×32 is unreadable on screen):

```bash
# real count (Studio cookies, or --source live)
ipixel-youtube --preview --channel @yourChannel --source live
# fixed number, no cookies
ipixel-youtube --preview --channel @yourChannel --preview-count 1093
pytest tests/test_matrix_32.py
```

## Useful options

| Option | Default | Purpose |
| --- | --- | --- |
| `--channel` | *(required)* | Handle or `UC…` ID (`YOUTUBE_CHANNEL`) |
| `--address` | *(required)* | Bluetooth address (`IPIXEL_ADDRESS`) |
| `--interval` | `15` | Seconds between two updates |
| `--name` | YouTube name | Text at the top of the panel |
| `--brightness` | `100` | Overall panel brightness 0–100 (`IPIXEL_BRIGHTNESS`) |
| `--color` | cyan | Hex accent, e.g. `00d4ff` |
| `--save-slot` | `0` | ROM slot 1–10; `0` = live display. Requires `--static`. |
| `--wipe-slot` | `1` | Clears this slot on connect (`0` = clear nothing). |
| `--static` | | Still PNG, no animation. |
| `--image` | | PNG/GIF/JPEG instead of the YouTube HUD (32×32). |
| `--source studio` | `studio` | Exact YouTube Studio count (`--cookies`, `YOUTUBE_SOURCE`) |
| `--cookies` | `cookies.txt` | Owner's Netscape session |
| `--source live` | | Estimate, like public counters |
| `--source official` | | YouTube Data API (rounded, `--api-key` required) |
| `--print-count` | | Prints the count in the terminal, without Bluetooth |
| `--once` | | A single update, then exit (3 BLE tries max) |
| `--debug` | | Detailed logs: HTTP, Studio session, BLE, pypixelcolor, bleak (`YOUTUBE_DEBUG`) |
| `--preview` | | 32×32 simulation without Bluetooth, files in `./assets/preview/` |
| `--preview-count` | | Fixed number for `--preview` (no cookies, no count request) |
| `--preview-dir` | `assets/preview` | Folder for the generated PNG/GIF files |

Matching environment variables: `IPIXEL_ADDRESS`, `IPIXEL_BRIGHTNESS`, `YOUTUBE_CHANNEL`, `YOUTUBE_CHANNEL_NAME`, `YOUTUBE_SOURCE`, `YOUTUBE_API_KEY`, `YOUTUBE_COOKIES`, `YOUTUBE_DEBUG`. An empty variable counts as unset: the CLI default applies (the only source of defaults). Container only: `TZ` (log time zone), `HOST_DBUS_SOCKET` (default `/host/dbus/system_bus_socket`).

Exit codes: `0` OK, `1` network / Bluetooth / channel error, `2` invalid parameters.

## Exact count vs "live"

The official YouTube API rounds the subscriber count above 1,000 (1,093 → 1,090 / 1,100). Public counters (SocialCounts / Mixerno) interpolate between these steps: this is **not** *Current subscribers* in Studio.

`--source studio` (default) reads this count through your YouTube Studio session. The cookies expire from time to time: export `cookies.txt` again if the script says the session expired.
